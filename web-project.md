# Programming Project 1: Game-Themed Web Application

## Objective

Work in teams of **4 students** to design and implement a small **game-themed web application**.

The goal is to demonstrate your understanding of the web development basics covered in the course and to combine them into a working application.

Your project should use following technologies:

- **HTML** – structure and content
- **CSS** – styling and responsive layout
- **Vanilla JavaScript** – interaction and dynamic functionality
- **Python + Flask** – backend functionality
- **HTTP / API communication** – communication between frontend and backend
- **Data storage** on serverside – using e.g. text files/JSON
- At least one clear **game mechanic**, where the user's actions affect the game state

- Use of web frameworks like React is forbidden. 

## Project idea

The team may choose the theme and game idea by themselves. 

It's also ok to use one of the text-based ideas from previous course as a base.

The game should have a clear objective and a playable mechanic. It can be turn-based or real-time, single-player or multiplayer, but it should be playable in a web browser.

The project does not need to be a large or sophisticated game. **A small, complete and well-functioning application is better than a large unfinished one.**

## Minimum requirements

The application should:

1. Have a clear game idea and objective.
2. Have a playable game mechanic.
3. Use Flask as the backend.
4. Use JavaScript to communicate with the backend, e.g. using `fetch()`.
5. Store and update relevant game data.
6. Have a clear and consistent user interface.
7. Work as a complete application from start to finish.

## Teamwork

The project is completed in teams of four.

Each team member can have a clear area of responsibility, for example:

- Backend / Flask
- HTML / UI structure
- CSS / visual design
- JavaScript / API communication

Or you can divide the work in any other way that makes sense for your team.

However, **all team members are expected to participate in the development of the whole project**.

Use Git for version control. Each team member should make meaningful contributions to the project.

## Deliverables

The team submits:

- Working web application
- Source code in Git repository
  - Clean and well-commented code
- README with:

  - project description
  - team members
  - technologies used
  - instructions for running the application
  - short description of the division of work

The team will also give a short **10-15 minute presentation and demonstration** of the application.

# Assessment

The project is graded on a scale of **0–5**.

The final grade is based on both the quality of the project and the student's **individual participation and activity**.

### 5 – Excellent

The application is complete, functional and well-structured. It demonstrates a strong understanding of frontend and backend development. The student has participated actively throughout the project, made significant contributions, and can explain their own work and the overall solution.

### 4 – Very good

The application works well and meets the main requirements. The implementation demonstrates good understanding of the technologies. The student has participated actively and made clear, meaningful contributions.

### 3 – Good

The main requirements are fulfilled and the application is functional. There may be some technical or usability issues. The student has participated sufficiently and contributed to the project.

### 2 – Satisfactory

Only the basic requirements are fulfilled. The application has noticeable limitations or unfinished parts. The student's participation has been limited but sufficient to demonstrate some learning.

### 1 – Poor

The project is substantially incomplete or has major functional problems. The student's individual contribution and activity have been very limited.

### 0 – Fail

The project does not meet the minimum requirements, is not functional, or the student has not demonstrated sufficient individual participation or understanding of the project.

## Individual participation

Individual assessment considers:

- Active participation in the project
- Meaningful contribution to the code and/or other project work
- Participation in planning and problem-solving
- Ability to explain one's own contribution
- Ability to demonstrate an understanding of the overall application
- Collaboration and communication within the team
- Git commits and other evidence of development work
- Anonymous feedback from other team members


**All team members should be able to explain how the application works, not only their own part.**
